## Method

For each record the tool extracts: strict correctness and F1 from `evaluation`; whether generation reached `max_new_tokens`; whether an answer was parsed; the retrieved triples; and the tool calls in `full_prediction`. Two answer comparisons are used:

- the **strict** evaluator comparison already stored in `evaluation.correct`;
- a **normalized** comparison from `utils/answer_normalization.py` (case/punctuation, date precision, quantities and Mintaka answer-entity labels), used to flag formatting/alias mismatches the strict evaluator counts as errors, plus a century-ambiguity date rule for two-digit years such as `13-Jun-46` against `13 June 1946`.

Primary category rules, applied in order:

1. **Correct** - `evaluation.correct == 1`.
2. **Normalization mismatch** - strict-wrong but the normalized comparison matches (or a partial date match, flagged separately).
3. **Abstention** - `dont_know` or an explicit "I don't know".
4. **Truncation** - `reached_max_tokens`.
5. **Answer-format / parser failure** - no answer parsed (`prediction` is null/empty) without truncation.
6. **Wrong - reference present in retrieved triples** - answered and strict-wrong, yet the reference string occurs in a retrieved triple (a selection or composition error).
7. **Wrong - reference absent from retrieved triples** - answered and strict-wrong, and the reference does not occur in any retrieved triple. This covers both genuine retrieval gaps and *derived* answers (counts, ages, differences, and yes/no comparisons) that are not expected to appear verbatim in the graph, so it is an upper bound on missing evidence.

The reference-in-triples test is a heuristic substring/word-boundary check, so it can be wrong for very short or numeric answers; it is reported as a signal, not a ground truth. Boolean (yes/no) references are flagged, since neither token can appear as a triple. Hallucinated triples are detected with the same check used by the `utils/logs_viewer.py` viewer: a triple written in the text that the constrained generator never produced (re-quotes are discounted; trailing cut-off lookups are excluded via `incomplete_triples` when available).

## Interpretation

The categories above split the teacher's errors into the mechanically detectable part (truncation and unparsed answers) and the semantic part (retrieval gaps, grounding/composition errors and normalization mismatches). Because these runs are on training splits, the split matters for the paper's data pipeline:

- **Truncation** removes otherwise-supervisable traces from the SFT pool; if it concentrates in count/ordinal/superlative questions it biases the mixture exactly where the new behaviours are weakest.
- **Wrong answers with the reference absent from the triples** mix genuine retrieval gaps with derived answers (counts, ages, differences, boolean comparisons); the per-type breakdown separates the two, and traces whose supporting facts were never retrieved should be filtered rather than imitated.
- **Wrong answers whose reference is present in the triples** are the most valuable negatives: the fact was retrieved and still mis-selected or mis-composed, so they are informative for DPO/RL data selection and for the multi-hop analysis.
- **Normalization mismatches** are pipeline bugs rather than model errors; they inflate the error rate and should be fixed in evaluation before the numbers are reported.

See `ERROR_CATEGORIZATION_GUIDE.md` for the manual, evidence-based procedure to confirm individual cases and `error_categorization_report.md` for the interpretation of the held-out test runs.
